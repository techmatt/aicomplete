# aicomplete

**AI Complete**, a cooperative board game about AIs, being turned into a digital version.
The rules live in a pure, deterministic Rust core that simulates them. A native simulator
and a wasm build for a JS front end sit on top of the core, and neither holds any rules.

Where to look: how to build and test is below; the rest has its own page.

## Layout

| Path | What it is |
|---|---|
| `crates/aic-core` | The rules engine (invariants: [docs/architecture.md](docs/architecture.md)). `Rules::new(config)` then `new_game` / `legal_actions_into` / `apply_mut`, plus the free functions `legal_actions`, `apply`, `view`. |
| `crates/aic-core/src/modules/` | One file per rules area (`alignment`, `economy`, `ai`), or a directory for the big ones (`adversary/`, `board/`, `cards/`, `threats/`), shared code (`common`, `effects/`), read-only forecasts of rules steps that the rule and the agents share (`plan`), the registry in `mod.rs`. |
| `crates/aic-sim` | Native CLI (a library, `lib.rs`, that `main.rs` calls; [docs/simulator.md](docs/simulator.md)); the agent skill ladder (`agents/`) and the experiment harness (`experiment.rs`, `experiment_run.rs`, `gate.rs`, `report/`); `farm.rs` is a read's games for remote workers; `cli.rs` parses the arguments; `play.rs` is `run`, `compare`, `replay` and traces; `docs/` generates and checks the docs; `prof.rs` is the `profile` feature. |
| `experiments/` | Experiment specs, and `results/<name>/`: committed cycle reports (old-revision records there, r6 to r14, don't load). At the top level: the standing specs (`band`, `gate`, `gate-exploit` and `gate-c3` its fast read and 3-country checks, `smoke`, `use` the engine and loop smoke, `same` and `same-noplanner` the identical-games checks, `ladder-v0`, `overlay-card-cost`, `sanity-line`) and those of the current revision. `farm/`: farmed specs. `archive/`: every spec not tied to the current revision, and those the binary refuses today. |
| `crates/aic-wasm` | wasm-bindgen bindings, JSON strings in and out. |
| `crates/aic-farm` | The farm's wasm bundle: `aic-sim`'s farm in a browser tab, with the configs and `experiments/farm/` specs built in ([docs/simulator.md](docs/simulator.md), *The farm*). |
| `content/` | Data embedded at compile time: `map.json` (pieces, layouts for 1–4 countries, setup), `cards.json`, `threats.json`, `adversary.json`, `ais.json`, `alignment.json` (the Unity and Discord decks), `projects.json` (the adversary's project deck), all built from code primitives. |
| `drafts/adversary/` | The source of `threats.json`, `projects.json` and `adversary.json` (threat tiers, projects, the Militarist): edit these, not `content/`. `python scripts/content/load_adversary.py` writes `content/` and docs/adversary-cards.md; `--check` (regen runs it) refuses a stale `content/`. |
| `configs/` | Game configs: modules, variants, every parameter. `baseline.json` is the current baseline at `RULES_REVISION`: the deck, 2 countries (3 seat the Researcher), difficulty 0, every number still a candidate; `experiments/configs/no_liberate.json` and `no_tier2.json` are derived from it (`regen.py` rewrites them). Other country counts, difficulties, off-variants and optional modules are `--set` lines ([docs/simulator.md](docs/simulator.md)). `configs/agents/` is agent numbers, not a game config: `values.json` (the value table) and `strategies.json`; changing one changes no rule (docs/agents.md). |
| `scripts/` | See [docs/scripts.md](docs/scripts.md). |
| `docs/` | The pages listed above. |
| `tools/card-art/` | Card frames, icons, scenes and print ([README](tools/card-art/README.md)). |
| `art/` | Committed frame masters and guides. Scenes live in `art-originals/`, a git-ignored junction. |
| `picks/` | Matt's picks: manifests of the pickers' rounds. |
| `web/` | Browser viewer (Vite + TS on `aic-wasm`). See [web/README.md](web/README.md). |

## Viewer

```sh
cd web && npm install && npm run dev               # builds the wasm (~9 s warm), serves http://localhost:5173/
```

Reloads on edits; records, `npm run e2e` and the rest: [web/README.md](web/README.md).

## Card viewer

```sh
cd web && npm run cards                            # exports, then serves http://localhost:5180/cards.html until stopped
```

Conductor's button runs it: keep the command, port and path as they are. The rest is in
[web/README.md](web/README.md#card-viewer) and [tools/card-art/README.md](tools/card-art/README.md).

## Card text for review

```sh
python scripts/cards/deck_text.py unity              # one deck as plain text: name, tags, location, cost, each line
python scripts/cards/deck_text.py science threats1   # several; `all` for every deck, `--list` for their names
```

Decks: `player` or one tag, `unity`, `discord`, `board`, `events`, `threats1`, `threats2`, `projects`. It reads the
generated docs, so after a content edit run `python scripts/regen.py` first. Redirect to a file to copy from it.

## Toolchain

- Rust stable (built with 1.98.1), target `wasm32-unknown-unknown`
  (`rustup target add wasm32-unknown-unknown`).
- wasm-pack (`cargo install wasm-pack --locked`); Node (built with 24) for the smoke test.

## Build and test

```sh
cargo build --workspace
cargo check --tests                                # a missing import in ~1 min, before a full test build
cargo test --workspace                             # fast lane: ~5 s once built, ~13 s after an aic-sim edit; 4-6 min on a loaded box
cargo test-all                                     # full run, slow lane included: ~3.5 min on 6 test threads, rebuild included
cargo test-slow                                    # the slow lane alone: nearly all of that
cargo build --release -p aic-sim                   # ~30 s after an aic-sim edit, ~45 s after aic-core, ~1 min cold
./target/release/aic-sim docs                      # regenerate the generated docs (--check: report only)
wasm-pack build crates/aic-wasm --target web       # ~20 s cold, ~9 s warm -> crates/aic-wasm/pkg (git-ignored)
node scripts/farm/build.mjs out/bundle             # the farm's wasm bundle (~1 min cold)
node scripts/wasm-smoke.mjs                        # needs the wasm-pack line's pkg (`npm run wasm`'s web/src/wasm/ won't do); checks native = wasm
node scripts/wasm-parity.mjs [games]               # native = wasm over the variant matrix; ~22 s with 2 games a variant and agent; rebuilds a stale pkg
```

**Test lanes.** The slow lane is the tests marked `#[ignore = "slow lane: ..."]`: whole
search-agent games, the greedy experiment grid, and more seeds of the replay checks
whose first seed runs in the fast lane. `test-all` and `test-slow` are cargo aliases
(`.cargo/config.toml`) for `cargo test --workspace -- --include-ignored` and
`-- --ignored`; one slow test runs with `cargo test -p aic-sim -- --ignored <name>`.
Anything after an alias goes to the test binary, with no second `--` (`crates/aic-sim/tests/args_guard.rs`):
`cargo test-all --test-threads=3` caps test threads; cap build jobs with `CARGO_BUILD_JOBS=3` (a `-j` stops in a second,
which looks like a fast pass: check the exit code). Times are on this
machine, otherwise idle; the first test-profile build takes ~80 s more. `cargo test` runs
test binaries one after another, so the fast lane's wall clock is about the sum of each binary's
slowest test: a test looping over agents or variants splits into one test (or scoped thread) each. A red crate stops
the run: `cargo test --workspace --no-fail-fast [-- --include-ignored]` (a cargo flag: not through `test-all`, 177).

**Rules changes:** the `golden_game` test pins the final state of one fixed game
(baseline, seed `u64::MAX`, action *k* = legal action `(k × 7919) mod count`). If a rules change is
intended, bump `RULES_REVISION` in `crates/aic-core/src/lib.rs` (and `docs/rulebook.md`'s line 3 by hand: `aic-sim docs` refuses it stale) and update
`GOLDEN_REVISION` and `GOLDEN_FINGERPRINT` in `crates/aic-core/src/tests/mod.rs` and `GOLDEN`
in `scripts/wasm-smoke.mjs` (`wasm_smoke_expects_the_golden_fingerprint` fails until it and `GOLDEN_CONTENT` match). The
fingerprint covers the config and the final state less its measures (`stats`), so a rename that
plays the same moves it with no bump; a new counter doesn't. (A fast-lane test.) It also pins
`GOLDEN_CONTENT_HASH` (wasm-smoke `GOLDEN_CONTENT`), the content hash over raw bytes: a
content-only edit moves it with no bump unless play changes. Set the hash first, from `regen.py`'s "content hash"
line; then one `golden_game` run gives the fingerprint (it checks revision and fingerprint as a pair before the hash):
the failing assertion's left side. Copy both, never type them.
A new phase goes in `configs/baseline.json`'s `round` list and in every lab test config that lists its neighbor
(`adversary.compute` beside `adversary.reveal`), or it silently never runs there.

**This machine.**

- Content and `configs/agents/` are compiled into `aic-sim` (`include_str!`): an edit to `values.json` needs a
  rebuild. The game configs are read from the working directory, so an old binary runs from an old tree:
  `git archive <rev> configs | tar -x -C out/old`.
- A fresh worktree has no `web/node_modules`: `npm ci` in `web/` (about a minute) before `npm run cards:fit`.
- 6 cores, 12 threads: 12 workers give about 6 × one, not 12 ×.
- `samply` waits on a UAC prompt: profile with `bench/profile_win.py` (docs/speed.md).
- Check processes with PowerShell `Get-Process` or `Get-CimInstance`. `wmic` and `tasklist`
  hang for minutes under load, and a script guard on one stalls silently.
- Timing has no warning of other load (another session's tests can take half the cores): two
  separate runs don't compare; `speed.py pair` does.
- In a Bash background call `timeout` is the kill limit (default 10 minutes), and a waiter
  killed at it can leave `bash.exe.stackdump` in the repo root: delete it. Git Bash loops overrun their `timeout` when
  every thread is busy.
- Windows can't replace a running exe: copy it to `out/` (git-ignored) to run one build
  while rebuilding another. Never to `%TEMP%`.
- A cargo build that fails leaves the old exe in `target/release`: a launcher that copies it
  and starts a run must check the build's exit code (`scripts/run_sim.ps1` does). Don't edit
  source during a build: it breaks the build or bakes in a mix of old and new.
- Concurrent builds in one target dir corrupt incremental objects (LNK2019 on anon symbols):
  `cargo clean -p aic-core -p aic-sim -p aic-wasm`.
- Two checkouts sharing a `CARGO_TARGET_DIR` share `release/aic-sim.exe` and its fingerprints,
  so an old-against-new run can compare one binary with itself. Give each checkout its own
  target dir, and `md5sum` both binaries before a `pair` or `same_play`.
- Python writes cp1252 and CRLF here, to `open(p, 'w')` and to a redirected stdout: scripts
  `sys.stdout.reconfigure(encoding='utf-8', newline='\n')` and open with `encoding='utf-8',
  newline='\n'`. A CRLF list read by a Bash `read -r` loop hands on `20\r`.
- `timeout N cargo test` under load kills the compile and prints "could not compile" with no
  reason. Background it with a log. `npm run wasm` can pass 60 s under load: the same.
- A conductor `wait_for` on a cargo test log needs `fail: ""`: passing test names hold "errors"
  (`..._are_errors_not_panics ... ok`), which the default pattern stops on.
- In Git Bash `rm -rf out/x` also deletes `out/x.exe` (Cygwin's `.exe` matching). Bash turns `/c/...` into `C:/...`
  for a native program but not after an `=`: a `FILE=SPEC` argument takes `C:/...` paths.
- PowerShell `*>` writes UTF-16 logs, which Git Bash `grep` reads as empty: read them in PowerShell
  or write with `-Encoding utf8`.
- A marker from `Start-Process powershell -Command '...; "done" | Out-File'` may never appear.
  End a log with a line from a `-File` script, and wait on that.
