# aicomplete

**AI Complete**, a cooperative board game about AIs, being turned into a digital version.
The rules live in a pure, deterministic Rust core that simulates them. A native simulator
and a wasm build for a JS front end sit on top of the core, and neither holds any rules.

- [docs/principles.md](docs/principles.md): design pillars, difficulty targets, lenses,
  measures.
- [docs/cards.md](docs/cards.md): every player card (158 cards, from 023's set), generated
  from content and `web/card/faces.json` by `python scripts/cards/cards_doc.py`, after `aic-sim docs` (a fast-lane test fails if it is stale);
  the pricing reasoning is [docs/card-pricing.md](docs/card-pricing.md).
- [docs/rules.md](docs/rules.md): the rules as implemented, at `RULES_REVISION`, with
  every default and deviation. Its tables of content and tunables are generated (`aic-sim
  docs`; the list is in [docs/architecture.md](docs/architecture.md), *Generated docs*).
- [docs/rules-history.md](docs/rules-history.md): what each revision changed and whether
  each rule is locked or a candidate.
- [docs/ops.md](docs/ops.md): every op content can print and how often it is printed,
  generated from `op.rs` and content.
- [docs/harms.md](docs/harms.md): every harm by kind of source, generated by `aic-sim docs`;
  the fast lane fails if a distribution check breaks.
- [docs/ruleset-v0.md](docs/ruleset-v0.md): the v0 design draft as handed over.
- [docs/design-014-board.md](docs/design-014-board.md): the 014 design record, frozen as
  handed over.
- [docs/architecture.md](docs/architecture.md): modules, configs and tunables, the
  invariants, and how to add a module, variant or card.
- [docs/qa-findings.md](docs/qa-findings.md): every bug-hunt finding (fixed, deferred
  with a recommendation, or won't fix); read it before a hunt.
- [CLAUDE.md](CLAUDE.md): the working contract for executors.

## Layout

| Path | What it is |
|---|---|
| `crates/aic-core` | The rules engine. No I/O, no clock, seeded per-purpose RNG streams in the state, serde state, exact replay. `Rules::new(config)` then `new_game` / `legal_actions_into` / `apply_mut`, plus the convenient free functions `new_game`, `legal_actions`, `apply`. |
| `crates/aic-core/src/modules/` | One file per rules area (`adversary`, `threats`, `alignment`, `economy`, `ai`), or a directory for the big ones (`board/`, `cards/`), shared code (`common`, `effects/`), read-only forecasts for agents and clients (`plan`: the adversary's next build), the registry in `mod.rs`. |
| `crates/aic-sim` | Native CLI: seeded games over a seed range, one config or two side by side, with every game replay-checked; the agent skill ladder (`agents/`) and the experiment harness (`experiment.rs`, `experiment_run.rs`, `gate.rs`, `report/`); `sweep.rs` is `run` and `compare`. |
| `experiments/` | Experiment specs, and `results/<name>/`: committed cycle reports. Game records are kept only where they still replay (`screen-014-board/records/`); `payback-009-records/` is r3 history that did not replay: 038 deleted the records and kept its README. `archive/`: specs of past revisions (since 028 every spec not tied to the current one) and those the binary refuses today. [`history.md`](experiments/history.md): past sweeps, recipes and timings. |
| `crates/aic-wasm` | wasm-bindgen bindings, JSON strings in and out. |
| `content/` | Data embedded at compile time: `map.json` (piece shape, layouts for 1–4 countries, the four printed country pieces with their cities, ocean, setup buildings and megaproject), `cards.json`, `threats.json`, `adversary.json`, `ais.json`, `alignment.json` (the Unity and Discord decks), `projects.json` (the adversary's project deck), all built from code primitives. |
| `configs/` | Game configs: modules, variants, every parameter. `baseline.json` is the current baseline at `RULES_REVISION`: 158 cards, 2 countries, difficulty 0, every number still a candidate (what each revision changed: [docs/rules-history.md](docs/rules-history.md)); `shared_row.json` differs only in the threat variant (and name): it is derived, so after editing the baseline run `python scripts/configs/shared_row.py`; a core test fails until you do. Other country counts and difficulties: `--set countries=N`, `--set adversary.difficulty=N`. Off-variants (rules.md §9): `--set threats.variant=off`, `alignment.variant=off`, `cards.variant=off`. Alignment's options (rules.md §5): `alignment.variant=still`, `alignment.momentum_every=2`, `alignment.antimatter_discord=0`. Optional modules switch off whole (016 trimmed `requires`): `--set threats=off`, `cards=off`, `economy=off`. (021 removed the `cards.variant=free_keep` opt-in: keeps cost insight.) The 013 configs (`v0_untuned`, `clusters`, `assets`) went with the old board. |
| `scripts/` | See [Scripts](#scripts). |
| `web/` | Browser viewer (Vite + TS on `aic-wasm`): play any config and seed, watch and step through sim game records, copy bug reports. See [web/README.md](web/README.md). |

## Scripts

Current:

- `wasm-smoke.mjs`: plays one game through the wasm package in Node. `wasm-parity.mjs`

- `configs/shared_row.py`: regenerates `configs/shared_row.json` from the baseline.
- `cards/cards_doc.py`: regenerates `docs/cards.md`.
- `cards/screen.py`: the screen summary: a table of named columns over experiment outputs
  (`--columns a,b,c`, `--preset 041|034|028|018|016`, `--sources`, `--list`) and `--gate DIR`,
  each check against its own agent, with games per check when `results.json` has a `gate`
  key. `scripts/screens.py` holds what it shares with the kept scripts below.
- Kept for the results docs that cite them, each saying so at its top: `cards/screen_034.py`
  (a shim for `screen.py --preset 034`), `cards/screen_028.py` (r17), `cards/screen_027.py`
  (r16), `cards/screen_024.py` (r15); `screen_023.py` and `screen_022.py` still read r15; `cards/screen_021.py` (r12) runs, but its
  021 gate is no longer the gate.
- `bench/same_results.py` (012): compares two experiment outputs. `--map OLD=NEW` (026)
  renames in the old output first, for a rename that must play the same.
- `bench/same_play.py` (025): proves a refactor left play unchanged: a matrix of configs,
  countries, difficulties and variants, with every agent but the beam (030: rollout and
  planner too, which are what a speedup is for), on the old and new binaries, ~20 min a
  run on 12 threads; every saved game replays on the new binary. `run ... --threads N`
  (042) caps it on a shared machine: ~13 min a run on 4 threads at r20, two at once, and
  `compare` under a minute. Keep a copy of the old binary. Takes `--map` too (026): records are then compared by field, since a renamed
  state's fingerprint moves.
- `bench/speed.py` (030): games a minute per agent. `--threads N` caps the many-thread
  column of `table` and `pair` (default: leaves 4 hardware threads free). `pair OLD NEW --out
  FILE` runs each row on both binaries in turn, so the ratio holds on a busy machine: use it
  for a before and after. An OLD built on another baseline refuses today's config: `git show
  <rev>:configs/baseline.json > out/old-baseline.json`, then `--old-config
  out/old-baseline.json`. Across a config or rules change `pair` prints NOT LIKE FOR LIKE: the
  two play different games, so its ratio is speed times game length. `table SIM --out FILE` is one binary's rates (`rollout` alone takes ~20 min;
  `--only "planner c2"` for a row, and both keep the file's other rows). `compare BEFORE.json AFTER.json` reads two `table`
  files. `check SIM` is
  the standing check (about 2 min, on a quiet machine, always one thread): fails at 1.3 ×
  `scripts/bench/speed_baseline.json`, `--update` to move the baseline. *What r19 and r20
  cost* in [experiments/history.md](experiments/history.md) says why it is above r18's. Its
  planner row is four seeds (050; one seed read r18 to r20 as 6.7 × against 1.75 × on 16). It
  holds only within one rules revision: the baseline records its revision, and against
  another `check` prints NO VERDICT and exits 0. Read `per_decision.py` then, and `--update`.
  A `--update` compares a run with itself: run a plain `check` after it.
- `bench/per_decision.py OLD_ROOT NEW_ROOT` (040): rounds, decisions and ms per game and per
  decision on the same seeds, for telling longer games from a slower agent. 6 games is
  too few across rules revisions (042: the same two binaries read 1.73 × on 6 seeds, 1.66 ×
  on 16 others); `--games 16` or more.
- `bench/gate_stop_rate.py`: how often the gate's early stop flips a verdict.
- `bench/first_divergence.py OLD NEW` (046): where two runs of one spec first play differently,
  game by game.
- `tune/` (007-008): `sweep.py`, `log_table.py`, `engine_sweep.py`.

Deleted: `scripts/board/` and `scripts/alignment/` (048 #108; `--preset 016`, `018` cover
what survives, and git has them for the results docs that cite them). See

## Viewer

```sh
cd web && npm install && npm run dev               # builds the wasm (~9 s warm), serves http://localhost:5173/
npm run dev -- --port 61870                        # another port
```

The dev server rebuilds the wasm and reloads when `crates/` or `content/` change. Open a
record from `aic-sim --save` with *Open record…* or by dropping the file on the page.
Details, and the browser check (`npm run e2e`), are in [web/README.md](web/README.md).

- A fresh worktree has no `web/node_modules`: run `npm install` first. Nor has it
  `web/src/wasm/`: `npm run check` needs `npm run wasm` first.
- `npm run build` (release wasm, typecheck, vite) took 92 s cold; `wasm-pack build
  crates/aic-wasm --target web` plus `node scripts/wasm-smoke.mjs` about 21 s; `npm run
  e2e` against a running dev server about 15 s.
- On a fixed port: `npx vite --port $PORT --strictPort` from `web/`, then
  `AIC_URL=http://localhost:$PORT/ npm run e2e`.
- While Rust or content files are being edited, the dev server rebuilds the wasm and
  reloads mid-run, which breaks e2e (`Cannot read properties of undefined (reading
  'view')`). Check against a snapshot instead: `node scripts/build-wasm.mjs && npx vite
  build && npx vite preview --port $PORT --strictPort`.
- A backgrounded `npx vite preview` outlives its tool-runner wrapper when that is stopped at
  its time limit, so the port stays taken: stop the `node` process that holds it.
- **The sweep** (020, the bug hunt's checker): `npm run sweep -- --quick` from `web/` (with
  `AIC_URL`; needs a release `aic-sim`) plays and watches games and checks the page at the
  moments that matter. Cases, times and gotchas:
  [web/README.md](web/README.md#the-sweep).
- `web/scripts/shots-017.mjs`, `shots-019.mjs` and `shots-021.mjs` save the viewer shots of
  their items; how to run them is in [experiments/history.md](experiments/history.md).

## Card art

The card renderer is `web/card/` (`card.js`, `card.css`, `icons.js`, the generated
`faces.json`, `layout.json`, `containers/`, bundled `fonts/`): `renderCard(card, layout, frameUrl, fit)`
turns card content into HTML, in mm, so one template serves print and, later, the web
client. **Cards are composed live, never pre-baked:** composed cards and print sheets go
to `out/cards/` (git-ignored). Committed: frame templates (`art/frames/`), guides
(`art/guides/`), sliced containers, fonts. Changing a card's text or numbers changes no
asset. Picker previews are never committed: they go to the shared
`art-originals/picks/<picker>/`. Card art prompts live in
`tools/card-art/scenes.json`, apart from content, so changing a card's mechanics changes
neither its art nor its prompt.

**One master.** Every frame derives from `art/frames/r3/master.jpg` (`steel-event-3`), so borders, bevels and plates match. `npm run derive` makes the six
variants in `art/frames/r3/`, numbers in `tools/card-art/derive.json`: buildings restack
the frame's inside from master rows, adding a divider above the art; tier 2 tints the
steel gold; the enamel, found by hue, goes through the kind's colour ramp (event keeps the
master's). The frame holds the fixed structure; the renderer draws what varies: the
insight hexagon, requirement plates and 0–3 tags.

**Where it sits is what it is** (locked by Matt, 2026-10-29). Top strip: cost octagon,
insight hexagon, requirements, tags, nothing else. Above the art (buildings): what lasts,
income, *Effect:*, *Action:*. Below the art: what happens once, extra costs first, as
minus-icons. No box: gain now. Brown box: income. Dark frame: the adversary's pieces or
projects. Dashed outline: another card or player. A square tile is a resource, a disc a
token on a card, a bare silhouette a board piece, a ringed circle a tag. In the dark frame a
clock is a delay, a minus on a threat a jam. The cost group
follows Race for the Galaxy: a hexagon at about 70% of the octagon, in front of its lower
right, with a halo in the strip colour; at 0 insight it is omitted.

**Icons.** Containers are one painted sheet in the master's steel (`npm run containers --
--draw`, 65 s; without the flag it reslices the kept sheet into `web/card/containers/`).
Glyphs are vector, in `icons.js`. Tiles and discs are one blank each: `card.css` multiplies
the face to the resource's colour.

**Faces.** Generated, never written: `crates/aic-core/src/face.rs` turns a card's ops into
its icon lines and rules text, and `aic-sim docs` writes them to `web/card/faces.json`, one
card a line. A card's `text` in `content/cards.json` is refused at load, and the fast lane
fails if `faces.json` is stale. The grammar is in docs/rules.md, *The card grammar*. The
renderer fails on an icon word it doesn't know. `tools/card-art/samples.json` says which
card shows each variant and which buildings show the splay.

**Trim and splay.** `layout.json` is the frame as painted. `derive` scales every frame in,
so the outer steel edge lands 0.5 mm inside the trim (`inset_mm` 3.5, 90% wide, 92.6% tall),
and fills the bleed by mirroring the steel band. `inset()` in `card.js` carries the zones
with it. The splay offset is the distance from the trim to the banner: only a covered
card's strip shows, and the newer card covers its name.

Run from `tools/card-art/` (Node 24, system Chrome through `playwright-core`, one
browser; `npm ci` first):

- `npm run derive`: the six frames from the master, about 5 s.
- `npm run fit`: measures each frame's zones into `art/frames/r3/fit.json`, which the
  renderer uses instead of the guide, and prints any that differ from the master. Some
  octagons measure one pixel (0.08 mm) off it: flood-fill noise, the geometry is the same.
- `npm run render -- [variants] [--pdf]`: composes each variant's real card at 300 dpi
  (815×1110). With no variants named, also the splay, the icon sheet and a full check of
  every card in content (about 1.5 min: background it); with `--pdf`, `all-cards.pdf`
  (every real card at true size, 9 to an A4 page, 18 pages) and `splay.pdf`. Fails if a font fell back,
  anything printed leaves the safe zone (x 6–63, y 6–88 mm), a panel overflows or a
  requirement plate reaches the tags.
- `node sheet.mjs <out.png> <images…>`: a one-row inspection sheet.
- `npm run picker`: writes `picks/card_frames_r3.json` from `out/cards/`, with its images
  in `art-originals/picks/card_frames_r3/`. Stops if that folder isn't reachable (see
  *Originals*).
- `npm run guides`: six labelled guides plus unlabelled `-blocks` twins, from
  `layout.json`. The twins are what the image tool sees: labels invite text.
- `npm run gen -- steel-program-1 … --pool=3`: raw frame draws for a new direction: Codex CLI's `$imagegen` on Matt's ChatGPT Plus login, the wordwarriors route
  (`codex exec --json -s read-only`, the prompt on stdin, the guide on `-i`, the PNG
  collected from `~/.codex/generated_images/<thread>/`). No API key. Prompts are in
  `prompts.json`. It stops at the first usage-limit message. Its frames go to
  `art/frames/r3/`, which `fit` and `render` read by variant name only, so a draw is
  ignored until it is copied over `master.jpg`.

- `npm run scene-gen -- [scene_id …] [--pool=N]`: draws card scenes, the same Codex route,
  into `art-originals/scenes/<round>/raw/`, the whole of `batch` with no ids named. The pool
  (one scene per real card, grouped by tag) and the one preamble are in
  `tools/card-art/scenes.json`: a scene's `card` is a suggestion, not
  a binding. The latest, batch 4 (045): 60 draws at 3 at once, 31–103 s each, about 17.5 min, 17% of the
  window. A style
  line alone came back as detailed concept art; the `emphasis` line (never a
  photograph or 3D render, and what to do instead) is what pushes a draw towards illustration.
  "Near-future setting" alone gave a historical foundry and village: the preamble now
  says clean modern machinery, clothes and buildings, never historical.
- `npm run scene-picker`: from the raw draws, each scene cut to the program window's shape
  (`<id>.png`), its two cards from `batch` at 300 dpi (`cards/`), the same at true size
  (`cards.pdf`, about 260 MB for 80 cards), and `picks/<picker>.json` with previews, about
  45 s for 24, or about 2 min when writing through the Drive folder, about 3 min for 40
  or 60 (cards.pdf about 400 MB for 120 cards):
  background it. `npm ci` first in a fresh worktree. Runs at below-normal priority, one
  image at a time. Each new batch replaces `batch` in `scenes.json`, so the scenes already
  drawn are the row ids in `picks/scene_batch_<n>.json`. Passes the scene to
  `renderCard`'s `artUrl`, which centre-crops it to the window `fit` measured: 53.3×33.2 mm
  for program and event, 53.3×25.3 mm for buildings, so a building shows the middle 76%.
- All 158 card scenes are drawn and none remain; with the 6 adversary, Discord and Unity
  scenes that is 164. How each batch was chosen, and the first rounds' numbers, are in
  [experiments/history.md](experiments/history.md).
- **Originals:** `art-originals/` is a git-ignored junction to
  `C:\Code\gdrive-sync\aicomplete\art-originals` (`mklink /J art-originals <that path>`).
  The scripts other than the pickers fall back to that path. The pickers stop without the
  junction, because their manifests link `../art-originals`. `AIC_ART_ORIGINALS` overrides
  the folder for all of them: a picker then reads and writes images there, warns, and its
  manifest still links `../art-originals`, so the images show only where the junction
  points at that folder. `npm run scene-picker` stops first, naming the ids, if a raw draw
  is missing. Each round has its folder (`card-frames-r3/` holds the
  container sheet): full-size originals, `frames/` (815×1110 PNG) and `log.jsonl`.
  Retired rounds (`card-frames-r1`, `-r2`, `scenes/r1`) live in
  `C:\Code\gdrive-sync\aicomplete\archive\art-originals\`, same relative paths, outside the
  junction. `scenes/r1` there is the raw draws only: to rebuild the rest, export commit
  `06ef387`, copy `raw/` into its `art-originals/scenes/r1/`, and run `npm run scene-picker`.
- **The master's outer steel band lies in its bleed;** `derive` is what brings it inside
  the trim. Composed singles show the full bleed; the splay is trimmed.

## Build and test

```sh
cargo build --workspace
cargo test --workspace                             # fast lane: ~4 s once built, ~13 s after an edit in aic-sim (rebuild included); after every change
cargo test-all                                     # full run, slow lane included: ~1.5 min at r22 on 6 test threads (048), ~2 min with the test build
cargo test-slow                                    # the slow lane alone: nearly all of that
cargo build --release -p aic-sim                   # ~12 s
./target/release/aic-sim docs                      # regenerate the docs built from content and configs (--check: report only)
wasm-pack build crates/aic-wasm --target web       # ~20 s cold, ~9 s warm -> crates/aic-wasm/pkg (git-ignored)
node scripts/wasm-smoke.mjs                        # needs the wasm build; checks native = wasm
node scripts/wasm-parity.mjs [games]               # 020: native = wasm over the variant matrix (aic-sim records replayed in wasm); ~22 s with 2 games a variant and agent; rebuilds pkg if older than crates/aic-core, crates/aic-wasm, content/ or configs/
```

**Test lanes.** The slow lane is the tests marked `#[ignore = "slow lane: ..."]`: whole
search-agent games, the greedy experiment grid, and more seeds of the replay checks
whose first seed runs in the fast lane. `test-all` and `test-slow` are cargo aliases
(`.cargo/config.toml`) for `cargo test --workspace -- --include-ignored` and
`-- --ignored`; one slow test runs with `cargo test -p aic-sim -- --ignored <name>`.
`cargo test-all -- --test-threads=2` is the wrong form: the second `--` turns the flag into a
test-name filter, every binary runs nothing and passes (045), so `tests/args_guard.rs`, a test
with no harness that sees the same arguments, fails it. It can't catch a filter that merely
matches nothing. Anything after an alias goes to the test binary: `cargo test-all -j 3` stops in about a
second with "Unrecognized option: 'j'", which reads as a very fast pass if you only see
the background task end, so check the exit code. To cap build jobs use `cargo test
--workspace -j 3 -- --include-ignored`; `cargo test-all --test-threads=3` caps test
threads. A new test that takes more than about a second goes in the slow lane, ideally with a
cheaper fast-lane twin (fewer seeds, fewer actions). Times measured on this 12-thread
machine with nothing else heavy running (lanes remeasured in 025); the first build of the test profile takes about 40 s.

- The test profile is optimized (`[profile.test] opt-level = 1` in `Cargo.toml`;
  debug assertions and overflow checks stay on): unoptimized, the same tests took
  4 min. `opt-level = 2` built 6 s slower and ran no faster.
- `cargo test` runs test binaries one after another, so the fast lane's wall clock
  is roughly the sum of each binary's slowest test. Today that is
  `experiment_streams_games_and_resumes` and `experiment_reports_comparisons` (~1 s
  each).
- Per-test times: `RUSTC_BOOTSTRAP=1 target/debug/deps/<binary>.exe --include-ignored -Z
  unstable-options --report-time` (the binary paths are printed by `cargo test --no-run`).

**Rules changes:** the `golden_game` test pins the final state of one fixed game
(baseline, seed `u64::MAX`, action *k* = legal action `(k × 7919) mod count`; "always the
first action" can now pay and withdraw a threat counter forever). If a rules change is
intended, bump `RULES_REVISION` in `crates/aic-core/src/lib.rs` and update the
fingerprint in both `crates/aic-core/src/tests/mod.rs` (`GOLDEN_FINGERPRINT`) and
`scripts/wasm-smoke.mjs`. The fingerprint covers the whole final state, config `name`
included, so a rename that plays the same moves it with no bump. The revision is recorded with every sim result, so old and new results are
never mixed up.

**This machine.**

- 6 cores, 12 threads: 12 workers give about 6 × one, so never read "12 threads" as 12 ×
  in an estimate.
- Check processes with PowerShell `Get-Process` or `Get-CimInstance`. `wmic` and `tasklist`
  hang for minutes under load, and a script guard on one stalls silently.
- Timing has no warning of other load: another session's test suite can take half the
  cores. `speed.py pair` holds under it; two separate runs don't compare.
- In a Bash background call `timeout` is the kill limit (default 10 minutes), and a waiter
  killed at it can leave `bash.exe.stackdump` in the repo root: delete it. Git Bash loops overrun their `timeout` when
  every thread is busy.
- Windows can't replace a running exe: copy it to `out/` (git-ignored) to run one build
  while rebuilding another. Never to `%TEMP%`.
- On Windows a Python script printing a non-ASCII character to a redirected stdout writes
  cp1252, not UTF-8: scripts reconfigure stdout, and pass `encoding='utf-8'` to `open`.
- Bash heredocs holding Python fail here (triple quotes, and backslashes get mangled even
  with a quoted delimiter). Write scripts with the editor, not with `cat <<'EOF'`.

## Simulator

Always run the sim in release.

```sh
S=target/release/aic-sim
$S run configs/baseline.json --games 2000                          # the 014 board, 2 countries, difficulty 0
for n in 1 2 3 4; do $S run configs/baseline.json --games 500 --set countries=$n; done
$S compare configs/baseline.json configs/shared_row.json --games 2000  # threat variants
```

The output shows each config's hash, content hash and engine version, plus an
`A -> B` line listing every variant and parameter difference. The rows:

- `win %` (± standard error);
- rounds (mean, min..max);
- games by end reason and by end round;
- decisions per game, options per decision, forced decisions %, and max options;
- adversary ops per round (mean, and the max in any one round), and at setup;
- every module counter, averaged per game; a `*_round` counter (the round of the first corruption, of the first project) over the games that reached it ("mean where reached"), and a round's own counter (`_rNN`, `.rNN`) over the games that reached that round (020);
- `replay ok`;
- `wall ms/game`: the run's wall time over its games, all threads at once (so it falls with `--threads`).

**Replay check:** each game is replayed from seed + actions through `Rules` rebuilt from
the resolved config, and must equal the final state. The exit code is 1 on any
mismatch, and 2 on a bad config or bad arguments (including a seed range that
overflows `u64`).

**Game records** (`aic-game-record/1`, `aic_core::SavedGame`) are JSON: the resolved
config, the seed and the action list (one action per line), plus a `note` saying why the
game was saved (command, outcome, seed, selector, overrides) and the outcome, rounds,
final-state fingerprint, hashes, engine version and rules revision for checking the
replay. A saved record is the game the summary counted, not a second play. Only
`config`, `seed` and `actions` are required, so a hand-written record loads too. `aic-sim
replay <record.json>...` prints each record's seed, outcome and warnings (a different
rules revision, content or config hash, or final fingerprint), and exits 1 if any record
fails to load or replay or has a warning. Browser bug reports are checked the same way.

Saving every game of a big run is slow: Windows file writes are the bottleneck. A shell glob over more than a few
hundred records hits Windows' command-line length limit ("Argument list too long"), so
replay big sets in batches.

The random agent picks uniformly among all seats' legal actions, passes and choice
answers included. Treat it as a floor, not as a model of a weak team.

## Agents

The skill ladder (`crates/aic-sim/src/agents/`). One team agent drives every seat, with
hands and drafts open, and answers the "players choose" questions too. Agents play
through the public API only (`legal_actions_into`, `apply_mut`, `apply_to`, reading the state).

- **No peeking.** Before any search an agent replaces what the printed game hides with
  a guess from its own RNG (`agents/determinize.rs`): the player-card, threat and
  Unity/Discord decks are shuffled (contents are public, order is not); each hidden
  adversary-deck position gets an unseen printed card of its stage (stages are stacked and
  public; next round's card is face up, and the top cards stay put under Recon Sweep);
  every RNG stream is reseeded. The guess depends only
  on the public table and the agent's RNG; a test changes only hidden information and
  checks that decisions stay the same.
- **Own randomness.** Each agent's RNG is the game seed on a stream named after the agent
  kind, apart from every engine stream. Games replay from seed + actions, and results
  don't depend on `--threads`.
- **Decides at the top level:** the planner follows its line outside the action phase, so draft,
  keep and pending choices are the rollout policy's. Growth is the exception (046): scored at
  `choices` × 2 at the top level, plain `choices` inside rollouts, and the line follows it.
- **Heuristic** (`agents/eval.rs`, 014 board): win/loss; corrupted cities (`corrupted`
  30), a seat down to its last presence (`presence_danger` 60; 0.5 of that with two, 0.25 with three, 0.1 with four), aligned cities
  (`aligned` 8); adversary ambassadors (`adv_ambassador` 3 each, `on_piece` 2 more on a
  player piece, base or factory, `on_factory` 6 more on a factory), the pressure on cities
  not yet corrupted (`pressure` 0.7 × `corrupted` × (ambassadors and markers / threshold)², the
  threshold being `corrupt_at` as the face-up card lowers it), troops (`troop` 12); the
  Discord deck (`discord_danger` 40 per card short of 3 left: the empty tip loses) and the Unity deck (`unity_deck` 40 the same way: the last card wins, 028); the bar's blockers
  (`blocker` 2); Alignment (Unity and Discord tips made, each bucket's fill as a share of
  its next tip, the bar level, and each visible adversary project's fill as a share of
  its cost, `project` 30, 017); the players' board (presence
  4, nodes −25 (022, 020's D9: was −6, and agents made nodes when an equal free choice existed), owned factories 4 (an adversary-owned one −4), chips 2, cities/bases/stations in reach 0.5, owned stations 5 (a corrupted one −5),
  megaproject cubes 2 (adversary's −1), factories 0.5, hardening 1, player ambassadors
  5 in supply (018: was 3, below their 6-credit cost, so agents never bought one) / 2.5 on the board, and toward freeing a corrupted city `freeing` 2 ×
  `corrupted` × a share of the hold: gathered ambassadors, then, once enough are at hand, a climbing bonus for landing them, 027), corruption markers (`marker` 1 each, against), shields (`shield` 3); track income, resources, cards in hand and
  built; unpaid threats (one that waits counts `threat_waits` 0.5). Every weight is a parameter: `w.<name>=V` in an agent spec. The
  014 weights are hand-set, not swept.

| Spec | What it does | Budget parameters (defaults) |
|---|---|---|
| `random` | Uniform over legal actions. | none |
| `greedy` | One action at a time: each scored by the heuristic after it, its own choices resolved best-first. A pass scores the table as it is (else stalling beats stopping). | `samples` 1 (guesses averaged), `depth` 1 (actions looked ahead), `choices` 2 |
| `beam` | Beam search over the rest of the round's action sequences, scored at the start of the next round (the end-of-round preview); plans once, follows the plan while the table matches, replans when a draw or reveal differs from its guess. | `width` 6, `depth` 120 (steps), `branch` 0 (children per sequence, 0 = all), `choices` 2 (levels of an action's own choices resolved before scoring it; with 1, placing presence, which asks a hex, looks worthless and beam stops growing its engine) |
| `rollout` | Across rounds: the beam's `candidates` best end-of-round positions, each continued by `rollouts` greedy playouts for `horizon` more rounds on fresh guesses; best mean wins. | `width` 4, `depth` 120, `branch` 0, `choices` 2, `candidates` 3, `rollouts` 4, `horizon` 2 |
| `engine` | The heuristic in **horizon mode** (008): income (tracks, income buildings, rewards) is worth `w.horizon` × the resource's weight × the rounds left, and board production (aligned cities' energy, less what adversary ambassadors divert) `w.production` of that (014: 1 won 65% at d0 against 37% with 0 on the checkpoint's map; level within noise at d1–d3 on the map since edited); the rounds left are the adversary deck's clock (deck plus the face-up card), cut short by when the team is on course to win (Unity Sway still needed for the Unity deck's last card at its rate so far, `w.unity_rate_start`, `w.win_lag`) and discounted by danger (`w.risk` per unit: unpaid threats per country, plus 0.5 with 1 Discord card or none left, plus 0.5 with a seat on its last presence); a building without income earns `w.ability` per round left, and a program in play a flat `w.program`; a card dealt into the draft packet counts as drafted less `w.packet_keep` × its keep price (023), and drafted and packet cards count only as far as the round's insight keeps them, best first (`w.packet_budget` 1, 046); a card in hand counts by the chance it can be paid for before the end (credits and antimatter, from what the seat has and earns, factory credits included; `w.insight_wait` 1 also queues the hand for insight, but as written it made playing any card look costly and cut wins to 4%, so it is off); resources fade when fewer than `w.spend_horizon` rounds are left; and the **deck clock** (011, `w.clock`): a penalty per round the team, at its Unity rate so far, would still be short of the Unity deck's last card (`alignment.unity_cards`) when the deck runs out. Searched like greedy by default; `width` > 0 makes it a beam over the round, `candidates` > 0 adds rollouts. | `width` 0, `samples` 1, `choices` 2; beam: `depth` 120, `branch` 0, `candidates` 0, `rollouts` 2, `horizon` 1. Weights: `horizon` 1, `hand` 1, `hand_cost` 0.2, `built` 1, `built_cost` 0, `risk` 0.1, `ability` 0.5, `spend_horizon` 2, `unity_rate_start` 2 (`opp_rate` still accepted), `win_lag` 1, `production` 1, `insight_wait` 0, `clock` 30, `packet_keep` 1 (023), `packet_budget` 1 (046) |
| `planner` | 028 (`agents/planner.rs`): the engine, with a shortlist of alternatives in the action phase each rolled out to the first decision of round `horizon` rounds on, with the engine as the policy, and the best line by the heuristic taken. A line runs on the real state (**full information**, Matt, 2026-10-29), so it is the game that follows; each decision inside it is still scored on a guess, because scored on open decks the one-step heuristic wins 19% against 59% (it drafts by printed cost). Draft and keeps follow the engine. **Speed:** the line being followed is reused, so a decision pays only for its alternatives. | `horizon` 2, `alts` 2 a decision, `budget` 8 a round, `margin` 40 (only actions this close to the engine's best), `choices` 2, `samples` 1, `prune` 6 (actions each seat keeps through a phase of a rollout, after the phase's first full scoring). Its keep and dominance parameters are the engine's: `planner:never_tag=2` holds the check in its rollouts too. `--quick` keeps it. |

**Keeping by plan and the dominance checks (022, `agents/policy.rs`).** Greedy and
engine keep drafted cards by a plan (`plan_keep` 1; 0 lets the heuristic decide keeps,
as before 022): at its first keep of the round a seat sketches this round's action phase
and the next three (`plan_rounds` 4; credits, insight, chips, energy and antimatter from what it holds and
its income; insight resets each round, the rest carries over), fills each round's
budget with the cards it would play (hand plus the candidates) in value-per-cost order
(value: the card's printed cost in credits, antimatter 3, insight 2, a lowered income
point 3, plus 1; cost: what this seat pays, its building discount off), and keeps each
drafted card, best ratio first, only if the plan with it is worth more than without it
(a play waiting a round is worth 15% less; 046: each marker in reach a card would clear, threat it would delay and shield it prints adds `plan_niche` 3 to the card's value). The dominance checks are the same agents with
one behaviour forced: `keep_all=1`, `keep_k=2`, `tier1_only=1`, `tier2_rush=1`,
`no_powers=1`, `no_counters=1`, `no_presence=1` (`docs/principles.md`, *Dominance
checks*).

The keep plan also charges credits paid for keeps (`plan_credit` 3), skips cards it can't
play now and holds back `plan_reserve` (0) insight in later rounds; `plan_hand` and
`plan_t2` exist for probes and are off. In `agents/eval.rs`, credits beyond `w.credit_cap`
(12) a seat are worth `w.credit_idle` (0.15), and `w.guard` prices an adversary ambassador
next to a corrupted city.

Any agent can use horizon mode (`greedy:w.horizon=1,...`); `engine` only changes the
defaults. Agent sweeps with strategy health (win %, buildings and tier-2 cards played per
game, the top buildings) go through `scripts/tune/engine_sweep.py`; it logs to
`out/tune/engine.jsonl`, and `AIC_SIM` points it at another binary (an absolute Windows
path; build one with `CARGO_TARGET_DIR=target/alt` to sweep while editing). Measured: 48
games at difficulty 4 on 12 threads take about 45 s for greedy and `engine`, 2 min with
`samples=3`, 4 min for `engine:width=4`, and longer with rollouts.

Spec syntax: `kind[:key=value,...]`, for example `beam:width=12`,
`rollout:rollouts=8,horizon=3`, `greedy:w.corrupted=40`. `aic-sim run ... --agent SPEC` plays
any of them; an experiment lists several.

**Content levers run on one binary (040).** A variant's `set` (or `--set`) takes a content
overlay, `<table>.<id>.<path>=<JSON>`: tables `cards`, `threats`, `adversary`, `ais`,
`alignment`, `projects`; `*` for every id; a path through fields and list indexes.
`cards.telemetry_archive.cost=3`, `cards.turnkey_factory.effects=[]`,
`cards.turnkey_factory.passives.0.amount=2`, `ais.*.presence.4.cost=2`,
`threats.<id>.counter=[["credits",3]]`. It goes through the same parsing and checks as
`content/`, so a typo or an illegal op is an error naming the entry. The overlay lands in
the config (`content`), so the config hash, `content_hash` and every saved record name
it and `aic-sim replay` needs nothing else. `experiments/overlay-card-cost.json` is a
worked sweep. The map is out of reach. Only player-card text is generated, so a threat's,
project's, adversary or Alignment card's text keeps its printed numbers, and the viewer
reads the printed content (`wasm.content()`): faces, adversary rows and power labels of
an overlaid record show the printed values, though the game plays the overlay.

**Gate early-stopping (040).** A spec with `"gate": {"z": 2.0, "min_games": 8, "every": 4}`
treats `planner:<check>` as a check of `planner` in the same variant and difficulty, and
`games` as each check's cap. Seeds go in blocks (8, then 4 at a time); after each block a
check stops if its gap clears `z` standard errors (sign test) or the seeds left can't turn
its sign back at that noise; an agent runs until its last check stops. The verdict is the
gap's sign, as in the old `--gate` tables. Decisions come only from finished blocks, so
the games played don't depend on threads or timing, and `--resume` rebuilds them from
`games.jsonl`. A panicked game counts for neither side and fails the gate (*A game that panics*). `report.md`'s *Gate* section and `results.json`'s `gate` give each check's
games, why it stopped, and the game time against an estimate at the cap. Measured: `python
scripts/bench/gate_stop_rate.py [z]` simulates the rule; at `z` 2 a level check stops early
about half the time and about 1% of runs get the sign the cap wouldn't. `experiments/archive/gate-034.json`
is the 034 gate this way: **872 of 1,728 games, 4.2 h of game time against 7.1 h at the cap and
5.5 h for 034's hand-cut plan, 1h 4m on 4 below-normal threads**, every verdict the same
(`experiments/results/gate-034-earlystop/gate.md`).

**A game that panics (050).** It fails alone: the run goes on, stderr and `failed.jsonl`
name its seed, config, overrides and panic, `report.md` lists them under *Failed games* with
the line that plays it again, `results.json` has `games_failed`, no measure counts it, and the
run exits 1. `--resume` plays it again. A spec's `"inject_panic": {"cell": 1, "seed": 51}`
makes one on purpose, for a test. `aic-sim run` and `compare` have no such net: a panic there
ends the run.

to `out/tune/log.jsonl`. `log_table.py TAG...` turns logged rows into a markdown table.

**Speed.** The agents are 99% of a run, and since 030 nearly all of that is the
heuristic and the rules, not state copies: a clone is 1.8 µs (it was 21), because names
are interned `Key`s, maps are sorted `FlatMap`s and hexes, piles, RNG streams and
per-round counters are shared until written (`crates/aic-core/src/key.rs`, *No hash-order
leaks* in docs/architecture.md). `aic-sim` uses **mimalloc** (on 12 threads Windows'
heap serialized the clones), and searches call `Rules::apply_to` (one state copy, not
two). Legal-action generation is 0.1% of a run: caching it buys nothing. For what 12
threads are worth here, see *This machine*.

To see the split: every run prints it (`time: ...` on stderr, and in the report's
*Timing*); `cargo build --release -p aic-sim --features profile` adds the search's own
split (apply, clone, legal, heuristic, determinization, planner lines) with call counts,
and allocations a game, from `experiment`. For a long screen, `cargo build --profile
fast -p aic-sim` (`target/fast/`) is 8% faster than release and takes minutes to build.
There is no sampling profiler here: to go finer, copy the tree and add timers to the
copy. Timers in the core break its no-clock rule.

Pricing a hand goes through `cards::prices`, and anything counting several tags through
`cards::tag_counts`: a tag count walks the seat's cards.

Compare two binaries with
`pair`, not two `table` runs: a test suite elsewhere on the box halved a whole table.

`planner:budget=4` runs 25-29% faster and wins 19 and 28 points fewer at 2 and 3 countries;
`prune=3` and `alts=1` save nothing (32 seeds, d2): leave them. `python
scripts/bench/same_results.py DIR_A DIR_B` compares two experiment output directories,
timing aside: the check that a speed-up changed no game. `same_play.py` is the wider one.

**Results as they go.** Every finished game is appended to `DIR/games.jsonl` (a header
line with the spec, engine, rules revision and content hash, then one game per line,
actions included), and the whole report is rewritten from the games so far every
`--report-every` seconds (default 60; files are written whole and renamed into place),
marked **Partial: N of M games** at the top. A stopped or killed run leaves both.
`--resume` (same spec, same `--out`) reads the stream back, replays each game to rebuild
it, plays only the games missing and reports them all; a different spec, edited config
file, engine, rules revision or content is refused. Without `--resume`, an earlier
stream in the directory is moved to `games.jsonl.bak`. A partial report that can't be
written (say, `games.csv` open in a spreadsheet, which locks it on Windows) is skipped
with a warning; the run goes on. Games are handed out seed by seed across all cells, so
a stopped run has every cell's first seeds.

**Fast by default (`--quick`).** Until the rules are close to final, scoping runs use
shallow agents and short runs (`docs/principles.md`): `--quick` keeps only shallow agents
(random, greedy and engine at their defaults, and the planner; beam, rollout,
`samples`/`depth` > 1 and `engine:width` > 0 are dropped). The only sign is one stderr
line (`--quick: dropped deep-search agents ...`), and the report's cells just lack them, so
an `engine:samples=2` you meant to compare is easy to lose. It caps seeds at 16 per cell unless
`--games` is given, and turns the probes off unless `--winprob`/`--closeness` is given.

Agent parameters come in two kinds: search settings go bare, heuristic weights need the
`w.` prefix (`engine:samples=2`, `engine:w.packet_keep=0.5`). An unprefixed weight is an
error, not a no-op.

`cards.csv` is split by agent, variant, config and difficulty (columns `agent,variant,config,difficulty,card,...`), so per-lever card numbers no longer need a spec per variant. The card table in `report.md` and `results.json` still pools per agent.

Don't read an agent's keeps as a human's. Up to r3 (007, 009) agents kept nearly every
drafted card, so a keep-priced lever measured the agent; 022 and 034 made them
keep-aware, and at r19 greedy, engine and planner keep 58-69% (d0, d2, 8 seeds a cell). It
is still their plan, not a table's.

A results dir's `report.md` exists from the start of a run: wait on the process or the
log's per-cell lines, not on the file.

Variant sweeps: an experiment file with several `variants`, each a list of `--set`
overrides (lists comma-separated, `alignment.unity_ease=1,1,2`).

`experiment` refuses a spec if its config names a parameter the binary lacks, so
re-measuring older rules with their binary needs a saved copy of that revision's config.

An experiment is configs × variants × difficulties × agents over a seed range, played
on every core (one game at a time per worker, results sorted, so nothing depends on the
thread count; every game is replay-checked). The spec (`experiments/*.json`):

| Field | Default | Meaning |
|---|---|---|
| `name`, `note` | | Report title and a line on what it is for. |
| `configs` | | Config files. |
| `variants` | `[{"name": "base", "set": []}]` | Named override sets in `--set` syntax, each applied to every config. |
| `difficulties` | `[0]` | `adversary.difficulty` levels. |
| `agents` | | Agent specs, weakest first. |
| `games`, `first_seed` | `first_seed` 0 | Seeds per cell. `--games`/`--seed` override. |
| `selection_seeds` | none | `{"first": N, "games": M}`: the seeds that picked a winner. Adds the report's *Fresh-seed confirmation*. Part of the spec, so `--resume` refuses a stream started without it. |
| `max_actions` | `5000` | Per-game cap (`timeout`). |
| `winprob` | `{"games": 0, "rollouts": 8, "agent": "greedy"}` | **Off unless set.** Win probability by round: for the first `games` seeds of each cell, `rollouts` playouts by `agent` from a guess of the table at the start of each round. `--winprob N` sets `games`. |
| `closeness` | `{"every": 0, "gap": 2.0}` | **Off unless set** (011; it was on, every 1). Probe every n-th real choice: 1-ply greedy scores of every option; close when the best two are within `gap` heuristic points (about credits). `--closeness N` sets `every`. |
| `records` | `4` | Records saved per category. |
| `gate` | none | `{"z", "min_games", "every"}`: early stopping; `games` becomes each check's cap, see *Gate early-stopping*. |
| `inject_panic` | none | `{"cell", "seed"}`: that game panics, see *A game that panics*. |

**Expensive measures are opt-in: screen first, probe finalists.** Win-probability
probes cost about 5× an experiment (007's `tune-after`: 45 minutes probed, 9–12
without), and closeness about one greedy decision per probed decision. Both are off
unless a spec or the command line turns them on. The two-stage pattern:

```sh
$S experiment experiments/x.json                                     # 1. screen: every variant, no probes
$S experiment experiments/x.json --variants keep2,uplinks \
    --winprob 10 --closeness 1 --out out/experiments/x-finalists     # 2. probe only the finalists
```

`--variants A,B` keeps only those variants of the spec (its first variant, the base,
is always kept, first, so the comparisons still have their reference). The report's
*Run* section says which measures were off.

The output directory (`--out`, default `out/experiments/<name>/`) holds `report.md` (the
cycle report: findings, then the tables), `results.json` (`aic-experiment/2`: the
spec, every cell's and group's measures, the card table, the records), `games.csv` (one
row per game; `economy_buildings_standing` follows `buildings_standing`) and `cards.csv`
(per agent, variant, config, difficulty and card), and `records/`, plus
`games.jsonl` (`aic-games/2`, written as the games finish; see *Results as they go*).

`results.json` and `report.md` also carry **agents paired, per variant** (`agent_pairs`,
*Agents paired, per variant*; none with a single agent): per config × variant × difficulty, A against B on
the same seeds with the paired standard error and sign test. `x:...` pairs with `x` if
listed; a bare agent with the next bare agent listed. With `selection_seeds`, **fresh-seed
confirmation** (`fresh_confirmation`, *Fresh-seed confirmation*): each variant against the
base on the seeds outside `selection_seeds` alone, the selection seeds' result beside it,
never pooled; it says so if no fresh seed has been played. `first_seed`/`games` must reach
past the selection range for any to exist.

**Measures** (all read from the public state or the actions, so the engine records
nothing extra):

- **Win rate** by agent × difficulty (± standard error), and the **skill gap**: the top
  tier's win rate minus the bottom tier's (each tier by its best agent, so a budget sweep
  of one kind is one rung), also on **survival**: the round a loss came in; a win counts
  its rounds plus the adversary cards left plus 2, so any win ranks above any loss.
  Survival is the ladder's signal while few games are won. *Ordered* means no tier does
  worse than the one below it.
- **Decision closeness**: forced decisions (one legal action), and of the real choices
  the share whose best two options are within `gap`.
- **Pick and play rates** per card: offered (in a draft packet), mean pick position
  (every dealt card is drafted by someone, so how early it goes is the signal), kept per
  offer, played per card gained (kept or drawn; per game for unique AI cards, which
  start in hand).
- **Economy buildings standing**: per game at the end, buildings with a passive `income`,
  `income_per_tag` or `income_if_tags` (27 of 56 at r19), by the base content even for a
  variant that overlays it. Token stores and `convert_upkeep` alone don't count.
- **Build variety**: distinct end-of-game builds (each seat's AI and buildings) and the
  mean Jaccard distance between two games' building sets, over all games and over wins.
- **Win probability by round** from the playouts; checkpoints that are uncertain
  (0.1 < p < 0.9); early lock-in (the result was decided, p ≤ 0.05 or ≥ 0.95 to the end,
  by round 2).
- **Margin**: on a win, adversary cards left (deck plus the face-up card: rounds to
  spare) and the adversary's ambassador supply left; on a loss, the adversary pieces over
  the current bar (`margin.level` is the bar level and `margin.unity_tips` the Unity tip
  count); every game, `margin.cities_corrupted_end` and `margin.cities_aligned_end`
  (also columns of `games.csv`, with the core's `adversary.corruptions`,
  `adversary.first_corruption_round`, `board.std_actions` and `board.war_destroyed`
  counters; every counter is in `games.jsonl`).
- **Game length**, ends by reason and round; **adversary operations** per round (mean,
  max) and at setup.
- **Help and counters**: gifts, payments and withdrawals per game; threats countered of
  those dealt.
- **Strategy health** (008), per cell × agent: buildings played per game (any card of
  kind `building`, AI uniques included), tier-2 cards played per game, cards played per
  game, and the share of wins with 2 or more buildings played (and standing at the
  end). A findings line per difficulty says whether the top agent plays buildings and
  tier 2. *Top agent*: the highest win rate at the spec's highest difficulty (ties to
  the later agent).
- **Head to head against greedy** (008): every agent against plain `greedy` (or the
  first greedy-kind agent) on the same seeds, per cell: won by both / only the agent /
  only greedy / neither, the win-rate difference ± the standard error of the per-seed
  difference, an exact two-sided sign test on the seeds only one of them won, and a
  verdict (*beats greedy* only when ahead with p < 0.05).
- **Variants against the base** and **removing a module** (008), when a spec has
  several variants: each variant's win rate against the first (the base), paired on
  seeds; for variants that switch a module off (`<module>=off`,
  `<module>.variant=off`), the base minus the off-variant: what the module is worth.
- **Luck share**: a two-way split of outcome variance over seeds × agents within each
  config/variant/difficulty: the seed's share (luck), the agent's (skill), the rest
  (interaction and the agents' own randomness). Raw sums-of-squares shares, no
  degrees-of-freedom correction. On win/loss and on survival.

The per-cell split (agent, probes, total) is in each report's *Timing* table and in
`games.csv`. Timings on older rules are in
[experiments/history.md](experiments/history.md).

**Saved records** (open in the viewer, or `aic-sim replay`), up to `records` each, with
the reason in the record's `note`: *close losses* at the top difficulty (fewest pieces
over the bar, then the longest games); *early lock-ins* (decided by round 2 in games of
3+ rounds, from the win-probability playouts); *surprising wins* (by the weakest agent,
after the playouts gave them ≤ 0.25, or below the top agent at the top difficulty).
"Weakest", "top" and "stronger first" are by **measured** strength (011), not ladder
tier: agents ranked by win rate at the top difficulty on the base variant (the same
reading as the strategy-health *top agent*); equal win rates share a rank, so with all
agents tied nobody is "weakest".
Files are named `<category>-c<cell>-<config>-<variant>-d<difficulty>-<agent>-seed<S>.json`;
a rerun into the same directory replaces them.
