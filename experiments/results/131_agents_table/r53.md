# 131: the value table per agent, the chip rate and auto_counter (r53, agents only)

No rules, card or price change, and no `RULES_REVISION` bump: the prompt's "r53" is 130's revision, which this item
plays. The scale throughout: 2 players, pairs B+P, B+R and P+R, d2.

## The table per agent

An agent spec's `t.<key>=v` sets one number of `configs/agents/values.json` for that agent: a resource
(`t.chips`), a rate, an op row's credits (`t.auto_counter`) or a token, or `t.<section>.<key>` for one in two
sections. `value::table_with` builds each distinct set once per process. `Eval::tbl` carries it to every reader in
`eval.rs`, `policy.rs` (the keep plan, the opening choice, the buried value) and `value.rs` (`Ctx::at`, `with_mix`,
`CardValue::of`'s Action at the agent's own rates under `Table::repriced`). A spec with no `t.` reads the table
itself. I chose this over loading the file at run time: wasm can't read a file, and one table per process can't run
two arms side by side.

Play is unchanged at the default table: on 288 games (36144-36191) both `strategist` / `greedy` and their
`t.chips=1.5` arms play the same games as main after 130, action for action (`screen-chips.md`, `--same`). Speed on
identical games (old binary `greedy` against new `greedy:t.chips=1.5,t.auto_counter=1.5`): 1.01 per decision.

## auto_counter: 1.5 → 0.67 a point

The measure (`measures.patch`, sim-only, on main after 130, seeds 36240-36335, 288 strategist games, `measure.md`)
counts each resolved threat by source and outcome, and whether an auto-counter of its type stood for it. It also
counts what each execution did, by counter and holding change.

- A cyber threat executed 32.6% of the time with no counter standing (1,279 threats), and 1.4% with Autonomous Defense
  Grid standing (69). The gap is 0.31 ± 0.02.
- 64 fires, so each fire saved 0.31 × 69 / 64 = 0.34 executions.
- A cyber execution costs 7.5 credits at the table: 1.04 Discord sways at `rates.sway` 4 (4.2), 3.0 compute at
  `drain_project` 1.1 (3.2), and some credits and nodes. This is a floor: Unity pulled back and sources made are left
  unpriced. No per-threat harm figure exists in `docs/harms.md` (it counts harms), so this is amendment #5440's
  fallback, 3.
- A fire is worth its cut, 8.7 (126, r50), plus 0.34 × 7.5 = 2.5, so 11.2 credits. The row is 0.3 fires a round ×
  11.2 / 5 points = 0.67.
- This re-read moves 126's numbers: a fire now cuts 3.95 points (253 points / 64 fires), against about 4.5 at r50.
  The cut at 126's mix would be about 7.6, giving a row of 0.61. I kept 126's 8.7.
- The saved share is likely high: the seats that held a counter were the stronger ones. The harm is likely low.

| read | seeds | strategist vs 1.5 | greedy vs 1.5 | ADG played a game (strategist) |
|---|---|---|---|---|
| factorial (auto_counter alone) | 36240-36335 | +0.3 ± 1.5 | −0.7 ± 0.7 | 0.17 → 0.07 |
| replication (auto_counter alone) | 36392-36487 | −0.7 ± 1.3 | +0.3 ± 0.8 | 0.12 → 0.04 |

At 0.67 the ledger reads Autonomous Defense Grid and Market Stabilization Board at 9.4 got against 11.5 given (9
credits + 1 insight at 2.5): a loss at the table. I asked Matt as a design question and took the default: keep
0.67, add no override, and flag both cards for more power.

## Speed

On identical games the new code costs 1.01 per decision. On the new table's games, `per_decision.py` (10-20 games)
read the strategist at 0.72-0.78 per decision and greedy at 1.16-2.25. Over the 288-game arms of the replication,
greedy ran 2.01 ms a decision at the new table against 2.83 at the old, and 1.76 against 1.70 in the factorial. The
cost is long-tailed by game, not by code, so the baseline was updated (`speed.py check --update`).
