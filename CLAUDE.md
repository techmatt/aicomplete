# CLAUDE.md

The standing contract for every executor working in this repo.

## What this repo is

**AI Complete**, a board game being turned into a digital version.

- The rules must stay playable as a printed board game. A digital-only mechanic
  (hidden bookkeeping, timing a human can't track) is a design change, not an
  implementation detail: flag it rather than build it.
- Intended shape: a **Rust core** that simulates the rules, with clients that render
  it. The first client is **wasm + a JS front-end**. Clients render and take input;
  rules live in the core.
- Design is still being gathered. The core implements the rules in
  [docs/rules.md](docs/rules.md) (revision `RULES_REVISION` in `crates/aic-core/src/lib.rs`):
  the board, the adversary, threats, Alignment and cards. The player cards are 023's
  candidate set ([docs/cards.md](docs/cards.md)); the AI-board, threat, adversary and
  megaproject content are placeholders pending redesign. Don't describe or document code as if it does more than it does.

## Engine rules

- The core invariants (no I/O, no clock, no global RNG, no hash-order leaks, serde
  state, exact replay, native = wasm) and how to add a module, variant or card are in
  [docs/architecture.md](docs/architecture.md). Keep them.
- Tunable numbers live in configs, never in code. A new mechanic is a module; another
  way of doing one is a variant.
- Any change to how games play out: bump `RULES_REVISION` and update the golden revision and
  fingerprint (`crates/aic-core/src/tests/mod.rs` and `scripts/wasm-smoke.mjs`). A prompt's
  revision number is a guess, since a bug hunt may have taken it: bump from the constant, and
  say so in the rules-history row and the report.
- Keep [docs/harms.md](docs/harms.md) current whenever threats, cards or adversary rules
  change: it is generated by `aic-sim docs` from content and `RULE_HARMS` in
  `crates/aic-sim/src/docs.rs`, and the fast lane fails if a distribution check breaks.
- Every rules change updates [docs/rules.md](docs/rules.md) and adds its row to
  [docs/rules-history.md](docs/rules-history.md) in the same commit. Run `aic-sim docs`
  after changing content or tunables, then `python scripts/cards/cards_doc.py` for
  docs/cards.md (it reads the faces docs writes): rules.md's tables, docs/ops.md,
  docs/harms.md and docs/cards.md are generated, and a fast-lane test fails if they are stale,
  or if rules.md backticks a `module.param` or `snake_case` name that is no tunable or op (or
  `NOT_TUNABLES` entry in `docs.rs`). Before the report, `git grep` each renamed name and each
  changed number: a diff doesn't show the prose it left stale. One home per rule: a rule's
  number lives in a config or in content, its effect in one `Op` arm or the rule that reads it.
- What content does is one schema, `Op` (`crates/aic-core/src/op.rs`); resources, tags
  and token types are enums (`vocab.rs`). Docs: *The op schema* in docs/architecture.md.

## Working rules

- **Commit to the branch you are on.** Leave nothing uncommitted.
- **Tests come in two lanes.** `cargo test --workspace` is the fast lane (~4 s once
  built): run it after every change. `cargo test-all` is the full run, the `#[ignore]`d
  slow lane included (~1.5 min at r22): run it before every commit. Flags follow the alias
  with no `--`: `cargo test-all --test-threads=2` (the `--` form makes the flag a test-name
  filter; a guard test refuses it). A test slower than about a second goes
  in the slow lane, with a cheaper fast-lane twin where one makes sense. Details in
  the README's *Build and test*.
- **Agents stay fast.** After a change to rules, state or agents, run `python
  scripts/bench/speed.py check target/release/aic-sim.exe`: it fails if an agent's ms/game
  is over 1.3 × `scripts/bench/speed_baseline.json`. It holds within one rules revision:
  across one it gives no verdict, and `bench/per_decision.py` says what the change cost. Run
  it after the first screen, not last, while a fix can still be tested. On a busy machine a failure proves nothing: run `speed.py pair OLD NEW --only engine` instead,
  which holds under load. A slowdown you mean to keep: say why in the report and `--update`
  the baseline.
- **Compare a lever with base on the same seeds, and confirm on fresh ones.** Pooling new
  seeds with the seeds that picked a winner is not confirmation: report the fresh seeds
  alone.
- **Write scripts with Write, not a Bash heredoc:** heredocs holding Python fail here. This
  box's other traps (6 cores, `wmic`/`tasklist` hangs, kill limits) are in the README's
  *This machine*.
- **Times are local, 12-hour clock** (2:45pm), in reports, docs and progress lines.
- **Background any step that takes more than ~30 seconds** (builds, tests, servers),
  and wait on the real process — the `cargo`/`node`/test binary — never on a
  launcher wrapper that returns before the work is done.
- **One cargo at a time in a target dir.** Concurrent builds corrupt incremental objects
  here (LNK2019 on anon symbols); `cargo clean -p aic-core -p aic-sim -p aic-wasm` clears
  it. Parallel helpers need their own `CARGO_TARGET_DIR`.
- **`npm run check` in a fresh worktree needs the wasm built first:** `cd web && npm install &&
  npm run wasm`. It typechecks against `web/src/wasm/`, which is git-ignored.
- **LF line endings.** `.gitattributes` sets `* text=auto eol=lf`; don't override it.
- **Operational facts go into `README.md`**: how to build, run and test, measured run
  times, ports, gotchas. Never leave one only in a report.

## Report

Write the report to the path conductor's preamble gives, starting with the header
it specifies:

```
status: done | partial | red
blocks: <what this blocks, or none>
carry: <what state.md should change, or none>
slow: none | <component> ~<time>, <why>, <what would fix it>
```

- Soft target about 60 lines.
- Findings, decisions and surprises only — no process narration.
- Mention tests only for a red you couldn't fix.
- Answer every amendment and message by number.
- End your final message with `Report written to <path>`.
